# Obscura Termux

**A native headless browser for Termux on Android**

Run JavaScript, scrape web pages, capture screenshots, and connect AI agents using MCP or the Chrome DevTools Protocol — on ARM64 Android with Bionic.

> **Experimental port:** This release is based on [Obscura v0.2.6](https://github.com/h4ckf0r0day/obscura/releases/tag/v0.2.6). It has been smoke-tested on Android 14 ARM64; full browser and feature compatibility have not been established. This project is not affiliated with or endorsed by upstream Obscura.

Obscura Termux runs natively against Android's **Bionic** C library. The release does not require PRoot, a glibc compatibility layer, Chromium, or Node.js for its standalone commands.

## Requirements

- **Termux** on Android 9 / API 28 or later. Android 9–13 have not yet been tested.
- **ARM64 / aarch64** device. Check with `uname -m`.
- Internet access to download the release.

## Install

In Termux, run:

```sh
pkg install curl tar coreutils
mkdir -p "$HOME/obscura-termux-install"
cd "$HOME/obscura-termux-install"
curl -fL -O https://github.com/bd-loser/obscura-termux/releases/download/v0.2.6/obscura-termux-v0.2.6-aarch64.tar.gz
curl -fL -O https://github.com/bd-loser/obscura-termux/releases/download/v0.2.6/SHA256SUMS
sha256sum -c SHA256SUMS && \
  tar -xzf obscura-termux-v0.2.6-aarch64.tar.gz && \
  install -m 755 obscura obscura-worker "$PREFIX/bin/" && \
  obscura --version
```

The archive contains both `obscura` and `obscura-worker`. The worker is needed for parallel scraping. The version output includes the upstream source commit (`8534b40`); upstream's workspace version is `0.1.0`.

To remove the installed binaries later:

```sh
rm "$PREFIX/bin/obscura" "$PREFIX/bin/obscura-worker"
```

## Quick start

```sh
# Run JavaScript and get a page title
obscura fetch https://example.com --eval 'document.title'

# Extract readable text or links
obscura fetch https://example.com --dump text
obscura fetch https://example.com --dump links

# Capture a PNG screenshot
obscura fetch https://example.com --screenshot page.png

# Scrape multiple pages using worker processes
obscura scrape https://example.com https://example.org --format json
```

For the full CLI and feature reference, see the [upstream Obscura README](https://github.com/h4ckf0r0day/obscura/tree/v0.2.6#readme).

## AI agents and browser automation

Start the MCP server for an agent that launches subprocesses:

```sh
obscura mcp
```

Start the CDP server for compatible browser automation clients:

```sh
obscura serve --port 9222
```

See the upstream [MCP guide](https://github.com/h4ckf0r0day/obscura/tree/v0.2.6#-mcp-model-context-protocol) and [Puppeteer / Playwright examples](https://github.com/h4ckf0r0day/obscura/tree/v0.2.6#puppeteer--playwright). Node.js is needed if you choose a Node-based client.

## How it works

The CI cross-compiles pinned Obscura source for `aarch64-linux-android` on Ubuntu with the Android NDK. It adds Android Bionic `errno` support to `deno_core`, links the required compiler runtime, and aligns the ELF TLS segment for Android ARM64.

**V8 is a prebuilt dependency:** the build downloads an unofficial Android ARM64 archive from [aidant/rusty_v8 v150.4.0](https://github.com/aidant/rusty_v8/releases/tag/v150.4.0) and verifies its SHA-256 hash. This project does not patch or build V8 from source. The archive's provenance has not been independently audited.

CI embeds a startup snapshot generated by the validated Android device build. It is pinned to the upstream source and V8 versions and must be regenerated and tested when those inputs change. The workflow checks the ELF loader and TLS alignment; runtime smoke testing is performed separately on a device. See [diagnostic findings](diagnostics/FINDINGS.md).

## Build from source

For a native Termux build, check out upstream [commit `8534b40`](https://github.com/h4ckf0r0day/obscura/commit/8534b401898ed17b62f69bdc3d5eb186bffb0d60), copy this repository's `termux` directory into that checkout, install matching Termux Rust and development packages, and run:

```sh
bash termux/build.sh
bash termux/smoke.sh target/release/obscura
```

The [Ubuntu cross-build workflow](.github/workflows/termux.yml) is manually triggered. It does not automatically build or publish new upstream releases. Termux Docker is useful for diagnostics, but its V8 snapshot behavior differed from the real device during this port.
